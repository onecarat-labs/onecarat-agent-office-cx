# フェーズ2 画面・操作設計案

2026-11-15。未実装の画面案。[詳細設計](PHASE2_DESIGN.md)に従う。今回の範囲では画面モック自体も実装しない。状態語はモックの状態と実機の事実を区別する。

## 共通構成

```text
上部：ONECARAT | モック・外部送信なし | 状態/エラー
左側：Office / Research Lab / 秘書 / 表示設定
中央：選択機能の一覧・詳細
右側または下部：根拠・成果・確認内容
```

既存live Officeは既存起動経路を維持し、新画面は専用mockインスタンスを推奨。画面内でliveへ切替えるトグルは設けない。Windowsの通常幅では一覧＋詳細、狭い幅では一覧→詳細→戻る。戻る操作で未保存の編集を黙って破棄せず、同一context内で保持する。context境界変更時の消去が優先する。

共通表示：未設定、空、読込中、更新中、成功、入力不正、結果不明、隔離、保存失敗。操作中は対象ボタンを無効化し処理中を表示。定期GETの失敗時は最終確認時点の表示とし、新規操作を停止。「再確認」は状態取得のみで、実行要求を再送しない。再接続/再起動で実行待ちが自動処理されないことを画面にも明示する。

エラー表示は「何が確認できないか」「影響する対象」「次にできる操作」を示す。内部RPC名や生エラー全文を主要な説明にしない。IDは根拠詳細で参照可能にする。全操作はキーボードで到達可能、フォーカス復元、色だけに依存しない状態表示、動きを減らす設定を維持。

## O2：Office

| 領域 | 内容・操作 |
|---|---|
| オフィス | メイン人物、観測済みサブエージェント、モック活動の識別、待機/作業/完了/失敗/不明 |
| 作業一覧 | OfficeセッションとLab/秘書のJobを種別付きで表示。JobとThreadを同じID体系にしない |
| 選択作業 | 最新状態、直近Turn結果、担当・観測根拠、成果数、関連画面へ移動 |
| 判断欄 | Codex承認と秘書の提案確認を別見出しで表示。モックの確認を実承認に流用しない |
| 活動 | 根拠イベントと最終観測時刻。作業名から状態を推定しない |

フロー：Jobを選択→人物/状態/根拠を確認→成果を見る→Labカードまたは秘書提案へ移動→戻ると選択を保持。予定だけのJobは「未開始」で、作業中人物を作らない。モックの分担/レビューは架空データと常時明記する。

表示設定案：同梱SVG人物2種と背景2種から選択（種類数は仮案、Q4）。プレビュー→適用→既定へ戻す。任意画像/URL/スクリプトの取込は対象外。外観だけを変え、完了根拠や権限は変えない。

## L2：Research Lab

```text
テーマ一覧                    選択テーマ
［テーマを追加］              質問 / 希望完了日時 / タイムゾーン
テーマA · 未開始              ［準備内容を確認］［モック実行］
テーマB · 結果あり            実行履歴：今回 / 過去のfixture
                              成果0〜10件［カード］［束］
                              詳細：出典 / 担当 / 不確実性 / レビュー
```

1. テーマを複数作成し、質問と希望完了日時を入力。未入力の時刻は「指定なし」。過去時刻、存在しない日付、タイムゾーン不正は入力エラー。
2. 準備内容でテーマ・日時・出力上限を確認。時刻は実行開始を意味しない。閉じて戻っても保存内容のみ保持。
3. 明示的な「モック実行」でfixture runを作る。複数テーマはまず1テーマずつ明示実行する案。並列一括起動はQ3判断まで見送る。
4. Officeに同じjobIdの架空活動を表示。要求受信/開始/カード受領/レビュー/終了を別々に扱う。
5. 成果カードを開くと要約・出典一覧・担当・不確実性・レビュー状態を表示。出典なしは「出典未確認」、0件は空結果。失敗時の部分成果はそのrun内に「未完了」として残し、成功結果に混ぜない。
6. 「深掘り」で元カードと追加質問を確認し、別のfixture runを作る。成果を元カードの束へ追加し、元runの10件制約を回避する上書きはしない。
7. 束の展開/折畳み、カードの並び替え、アーカイブを行う。初期案では破壊削除を避け、アーカイブ解除を提供。ドラッグに加え上下移動ボタンを設ける。
8. 「保存内容を確認」でローカル出力の内容をプレビュー。fixture出力を採用する場合のみ明示ボタンを追加。Driveは「後続フェーズ・未接続」と説明する。

不確実性とレビューは別フィールド。「レビュー済み」は対象revision、担当、コメントを伴い、カード本文の編集で再レビュー待ちとなる。モックレビューは実エージェントによる検証済みと表示しない。

日時案：利用者の希望完了時刻と解釈することを推奨（Q3）。模擬時計の操作は開発用fixture画面に限定し、時間を進めても自動送信は発生しない。期限到来/期限超過は別バッジで、実行成功/失敗とは別。

## S2：秘書

```text
架空の受信箱 / 架空の予定     対応提案
［fixtureを選択］             根拠 / 使用Skillと版 / 必要な対応
提案一覧 · 下書き/確認待ち    宛先・件名・本文 または 予定変更前後
                              ［修正する］［最終内容を確認］
                              モック確認（外部送信なし）
```

1. 同梱fixtureから受信メール/予定を選ぶ。「メールを取得済み」とは表示しない。
2. 有効なSkill版を選び、「提案をシミュレーション」で固定fixtureから返信案/予定変更案を生成。実モデルによる文章生成ではない。
3. 対話欄から修正依頼を入力。既知fixtureの修正だけ適用し、対応できない自由文は「モック未対応」と表示して直接編集へ案内。何でも理解したように振る舞わない（Q6）。
4. 宛先/本文/変更時刻等を直接編集し、revisionを更新。変更点を表示し、前の確認を失効。
5. 最終確認画面で今回の内容、参照元、Skill版、未確認点を表示。「修正へ戻る」「取り消す」「この内容でモック確認」を選択。
6. モック確認は疑似結果を返すのみ。「実送信済み」ではなく「シミュレーション完了・外部送信なし」。二重クリック/古い画面からの確認は再実行しない。

Skills画面：一覧、名前/説明/指示本文、版、有効/無効、プレビュー、保存。JSON等の任意コード実行を含めない。編集中のSkill更新を既存提案に黙って適用せず、提案が参照する版を固定する。シェル、OAuth、メール認証、権限設定の操作はこの画面に置かない。

メール/予定の定期確認と独立稼働は初回公開までの残要件。「定期実行を有効化」するボタンやOS登録はこの設計候補に含めない。

## 画面ごとの異常系

| ケース | 表示・操作 |
|---|---|
| 結果待ちのまま応答がない | 結果不明、同じ要求の再送不可、状態再確認のみ |
| 認証/接続context変更 | 内容・下書き・確認画面を消去し隔離の説明。旧カードへ戻るリンクも無効 |
| 10件超/循環束/不正URL | 固定エラーと修正対象。生データや危険HTMLを描画しない |
| 別タブで提案更新 | 「内容が更新されました」。自動確認せず最新版を再表示 |
| 保存失敗 | 保存済みと表示しない。編集内容は現contextのメモリに保持、境界変更なら消去が優先 |
| 取得していない情報 | 未確認と表示。担当/出典/完了を推測しない |

この画面案は、実承認・実通信断・実サービス操作の成立を示すものではない。
