## 実装

| 主なファイル | 責務 |
| --- | --- |
| src/codex.mjs | 通常ユーザー・バージョン確認、APIキーを継承しない環境、所有app-serverのstdio起動・終了 |
| src/rpc.mjs | JSONの行分割、要求ID対応、タイムアウト・通信断、再送なし |
| src/state.mjs | Thread/Turn/Item別の投影、完了・不明状態、サブエージェント受信構造、本文を含まない永続化用データ |
| src/runtime.mjs | ChatGPT状態、Thread作成・一覧・選択・read、入力/追加指示、承認管理、再接続照合 |
| src/server.mjs | 127.0.0.1 HTTP、起動ごとの認証、Host/Origin・CSRF検査、固定APIと静的ファイル |
| ui/ | 新規SVG人物、状態演出、セッション切替、会話、入力、承認・拒否、イベント、エラー |
| src/mock.mjs | 明示的なdemo用の架空RPC。モデルやコマンドを実行しない |
| tests/runtime.test.mjs | 単体・統合テスト |
| scripts/ | 構文検査、隔離実接続確認、Edge UI確認 |

実行時依存はNode.js標準機能のみ。JavaScript ES modulesを採用し、今回TypeScriptコンパイルやReactビルドは導入しない。小規模な初期UIとRPC境界を独立させ、型付きプロトコル導入は次の改善候補とする。接続factoryを注入する構造により、将来A方式の仲介transportを追加できる。C方式は未実装。保存データのschema=1、対応CLIバージョンは0.169.0に固定し、異なる版は起動拒否する。

CC版のpackage.json、MITライセンス、Figure.tsxを読み取り参照。SVG/CSSはCXの新規実装で、CCのコード・ブランド素材はコピーしていない。通常アプリはCCの配置・依存に依存しない。今回のブラウザテストだけは、既存CCフォルダ内にインストール済みのplaywright-coreを絶対パス指定で読み取り利用した。追加インストールなし。これは開発確認用のツール利用でありランタイム依存ではない。

## 安全境界・制限

- 既定のlive起動はモデル送信無効。将来の作者承認後にのみ明示フラグで有効化する。通常開発のfixtureは専用demoモードで、画面にも架空データと表示。
- Codexはread-only sandbox、on-request承認。外部機能・hooks・plugins・goals・multi_agent等を初期設定で無効化。MCP設定に有効サーバーがある場合はThread作成・送信を拒否し、設定自体は変更しない。
- UIの新規セッションは専用作業フォルダ。外部Threadの自動取込みをしない。メタデータとして知っているCX作成Threadだけを操作する。
- 接続復旧は明示ボタン。既知Threadをreadで照合するが、resumeしない。購読未復旧の旧Threadは参照のみ。別接続の詳細購読や作業継続は未対応。
- thread/readの履歴取得が拒否された場合は概要だけを再照会し、履歴利用不可として保持。失敗を成功扱いにして本文を捏造しない。
- 承認回答は送信前にロック。serverRequest/resolvedで回答済み/取消済みへ進み、切断時は結果不明。追加権限・ネットワーク承認や判断材料不足は受諾不可。未知要求は画面に未対応として残し、自動回答しない。
- 生のstderr、認証情報、入力、回答、承認コマンド/差分をCX診断ファイルに保存しない。UIの回答・差分はメモリのみ。Codex自体の正規rollout保存は別責務。永続化はThread ID、選択、最大200イベントのメタデータのみ。
- delta通知には安定した重複識別子がない場合があるため、完成Item本文を正とする。途中文字列の完全な重複排除は保証しない。
- 子エージェントはcollabAgentToolCallのreceiverThreadIdsだけを「観測」として表示する構造。各子の実作業・終了を推定しない。モデル実機では未検証。
