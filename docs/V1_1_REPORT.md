## 追補：起動デスクトップの制約

作者から「起動されていないように見える」との報告を受け、ウィンドウの所属デスクトップと入力デスクトップをWin32 APIで比較した。製品窓は `CodexSandboxDesktop-*`、利用者の入力デスクトップは `Default` だった。プロセス・handle・PrintWindowによる画像取得は成功していたが、利用者の通常画面へ表示されたことの証拠にはならなかった。上記環境での自然言語起動は、通常デスクトップへの表示まで完了できていない。

隔離デスクトップの境界を回避する実装は行わない。通常のPowerShellから、照合済みのIDを指定して `node C:/work/onecarat-agent-office-cx/scripts/launch-office.mjs --thread <Thread-ID>` を実行するのが代替手段。この手動起動後の利用者画面での確認は未実施。誤って起動した隔離側の窓はCloseMainWindowで終了し、Mutexを解放した。Codexは停止していない。

検証結果：全自動テスト94件成功。その後、子ログ併合時に委任時刻が保持される検査を加え、対象11件も再成功。ビルド・構文検査成功。ネイティブフォームの合成試験で日英、親を先頭固定、新しい子の優先、古い委任の再生禁止、完了後の委任禁止を確認した。委任中の画像を取得して、向き・衣装・役割表示・書類の位置を確認：[合成ログによる画面](../artifacts/v11/team-delegation.png)、[フォーム検査結果](../artifacts/v11/team-delegation.checks.json)。テスト窓は隔離デスクトップ上であり、通常画面への起動確認とは扱わない。実際の新規委任での更新版アニメーションは、利用者の再起動後の確認待ち。

実行物は `dist/v1.1/Onecarat-CX.exe`、同梱observerは同階層の `observer/`。Windows・.NET Framework 4.8・Node.js 24以上を前提とする。Node.jsは別途必要。

このプロジェクトのCodexで「Onecarat Agent Office CXを起動して」と依頼する。[Skill](../skills/office-cx/SKILL.md)とAGENTS.mdが、次の起動処理へ案内する。

```powershell
node C:/work/onecarat-agent-office-cx/scripts/launch-office.mjs
```

呼び出し元の `CODEX_THREAD_ID` とログ先頭のIDを照合する。通常のPowerShellやEXEのダブルクリックでは、呼び出し元Codexを特定できないため、IDなしで最新ログを選ばない。確認済みのIDを使用する場合だけ、ランチャーに `--thread <Thread-ID>` を付ける。

`.agents` は今回の実行環境で書き込み禁止のため、Skillを `skills/office-cx` に置き、プロジェクトのAGENTS.mdから利用する方式とした。自動登録されたスラッシュコマンドやグローバルSkillではない。別フォルダのCodexには上記絶対パスの起動を依頼できる。

## 実装した機能

- ステージ中心の小窓。壁の看板にOnecarat Labs / CODEX OFFICE。選択プルダウン・言語ボタン・ツールバーを廃止。
- 1セッション1ウィンドウ。ユーザーとThread IDを含む名前付きMutexで重複を防止し、再起動要求は既存窓へ通知する。別セッションは別位置へ配置する。
- 移動・サイズ変更・最小化。右クリックで最前面とアニメーション停止を切替可能。
- Windows表示言語APIで起動時に日本語または英語を選択。地域形式は参照しない。
- 実際の記録に応じた思考・調査・編集・コマンド等の演出。子の登場・作業・報告・退場は観測根拠がある場合だけ。
- ターン終了とセッション終了を区別。ターンが終わっても窓を閉じない。
- 承認イベントを取得できた場合、時間経過だけでは解除せず、古い要求や監視停止は「解決状況不明」と表示。複数要求を追跡する。
- UIへ渡す情報をID・固定状態・時刻等に限定。Codexへの入力・承認・実行制御・通信経路は設けない。

## 設計判断

| 判断 | 理由 |
|---|---|
| Node.js読取＋Windows Formsを継続 | 既存の安全なログ監視を再利用し、小窓を軽量なネイティブUIで実装できる |
| app-serverで別Threadを作らない | 新規Thread操作は、既存セッション観測の代替にならない |
| CODEX_THREAD_IDをログと照合 | 最新ファイルや共有される可能性のあるCODEX_SESSION_IDから現在セッションを推測しない |
| セッション単位のプロセスとMutex | 混入を防ぎ、1窓の障害を他窓やCodexへ波及させにくい |
| 自動終了なし | 現行の保存ログでセッション終了の確証を確認できない |
| 表示言語APIを使用 | CurrentUICultureの実行環境依存を避け、Windowsの表示言語を直接確認する |
| 承認取得不能を明示 | 実際に保存されないイベントを、ツール引数や経過時間から捏造しない |

## 実ログ・実機確認

Codex CLI 0.169.0の保存ログを読み取り、現在の開発セッションを観測した。検証のための新しいモデル呼び出し、別Codexセッションの作成、承認設定変更は行っていない。

| 確認方法 | 観測事実 | 証拠 |
|---|---|---|
| 7つの既存ログの構造を読み取り | 子のparent情報・活動を確認。承認要求は見つからなかった | [構造調査](../artifacts/v11/log-inventory.json) |
| 本セッションのworkerを短時間起動 | root ID一致、親＋以前実際に起動した子2つを取得。複数snapshotの活動状態とstdin終了後のworker停止を確認 | [実観測](../artifacts/v11/live-observer.json) |
| 製品ランチャーを2回実行 | 実窓が1つだけ存在し、同一handleを再利用。Windows表示言語はja。検証で作った窓だけ閉じた | [実起動結果](../artifacts/v11/live-launch.json)、[実画面](../artifacts/v11/live-window.png) |

実ログ検証で、子ログにコピーされた親のsession_metaにより子IDが上書きされる不具合を発見し修正した。ファイル自身のIDと一致する先頭metaを固定し、その開始以前の継承履歴を除外する。修正後は親と子2つを分離して取得できた。回帰テストも追加した。

## 制限・未検証

**承認待ちを実ログから常時検出できるとは言えない。** 確認した[Codex 0.169.0の保存ポリシー](https://raw.githubusercontent.com/openai/codex/rust-v0.169.0/codex-rs/rollout/src/policy.rs)では承認要求イベントは非永続扱い。現在の読取方式では取得できず、承認はCodex本体で確認する。取得できる形式に対する表示・解除照合は合成ログで検証した。

- 実際の新しい子が登場して報告・退場する全過程のライブ確認は今回未実施。既存の実在する子ログの識別と合成演出試験を分ける。
- セッション終了イベントは実ログ未確認。ターン終了からセッション終了を推測しない。
- 15秒無更新の通常活動は現在状態不明。長時間作業でもそうなる場合がある。
- 起動時の読取範囲や監視候補数には上限があり、全履歴を復元する製品ではない。
- Windows表示言語を実際に変更して再起動する試験、高DPI・複数モニター・長時間負荷の網羅検証は未実施。英語は言語判定関数とフォームの合成試験で確認。
- 窓を利用者が移動した後の配置、極端に多い同時窓では重なりを完全には防がない。
- Node.jsの同梱、インストーラー、署名、起動時登録、グローバルSkill登録は行っていない。

## 作者の確認手順

1. このプロジェクトのCodexで起動を依頼する。ブランドが壁にあり、現在のセッションID末尾がタイトルに出る。
2. 同じセッションで再度起動を依頼する。窓が増えない。
3. Codexへ通常の作業を依頼する。記録された活動に応じて動きが変わる。ターン終了後も窓は残る。
4. 別のCodexセッションでランチャーを実行するよう依頼する。別の専用窓が開く。
5. 小窓を移動・サイズ変更・最小化する。右クリックで最前面や動きを切り替えられる。
6. 小窓を閉じてもCodexが使えることを確認し、再度起動を依頼する。
